# Release policy

No binary, image or model is published merely because source is public. A
release candidate may be created only from a complete reviewed commit reachable
from the protected default branch.

## Required release gates

1. The source commit has passed all required checks and DCO verification.
2. The release tag matches `v*`, is protected from update and deletion, and is
   created only by an authorized maintainer.
3. Dependencies and GitHub Actions are immutably pinned and their licenses and
   purposes are recorded.
4. The candidate includes an artifact-specific SPDX or CycloneDX SBOM covering
   Rust, JavaScript, native libraries, plugins, containers and models actually
   distributed.
5. Each artifact has a published cryptographic checksum and verifiable build
   provenance tied to the source commit and build workflow.
6. Secret scanning, license review, vulnerability scanning and applicable
   interoperability checks pass with documented limitations.
7. LICENSE, NOTICE and third-party notice bundles accompany the artifact.

Release provenance must be generated by an isolated, least-privilege workflow;
the source repository's default `GITHUB_TOKEN` permission remains read-only.
Approval to publish source does not authorize publishing packages, binaries,
OCI images, models, releases or deployment configuration.

Protected rulesets are staged in `infra/github/rulesets/`. Required status-check
names remain intentionally unset until the first stable CI run establishes
their exact names and behavior.
