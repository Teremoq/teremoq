# Security policy

## Reporting a vulnerability

Report suspected vulnerabilities only through GitHub Private Vulnerability
Reporting for the affected repository. Open its **Security** tab, choose
**Advisories**, and select **Report a vulnerability**.

Do not disclose vulnerabilities in public issues, pull requests, Discussions,
commit messages or other public channels. This project does not publish an
email address for vulnerability intake.

Include the affected revision or tag, component, impact, reproduction steps and
a minimal proof of concept that contains no customer data, live credentials or
production identifiers. Do not test against systems you do not own or have
explicit authorization to assess.

## Scope and expectations

Reports about the source repositories and their documented development setup
are in scope. Private deployments, customer infrastructure and third-party
services are not public testing targets. Credentials, PKI runtime state,
customer namespaces and operational data must never be attached to a report.

Maintainers will triage reports according to availability and coordinate
disclosure through the private advisory. Publishing the source code does not
create a response-time commitment, SLA, warranty or commercial support
obligation.
