# Federation concurrency chaos harness

This harness characterizes the finite behavior that the pinned public APIs can
observe. It does **not** certify bounded relay concurrency: ADR-0006 records that
pending handshakes and active relay sessions remain unbounded in upstream
`moq-rs`.

## Safety model

- Every run creates a uniquely named Docker bridge and runner container.
- No host port is published; existing UDP/4433, UDP/4443 and other services are
  only inspected and never modified.
- `smoke` receives no Linux capability.
- An impaired `hostile` case grants only `NET_ADMIN` to its runner and applies
  `tc netem` only to that container's loopback interface. Hostile `baseline`
  receives no capability. The harness never uses `--privileged`.
- Both the in-container command and the host orchestrator install cleanup traps.
- The image reference is versioned and digest-pinned. No packages are installed
  by the run.
- PKI is generated by the bounded `rcgen` test helper in a `0700` temporary
  directory and deleted by RAII. The harness writes no certificate or key.

## Usage

```bash
./chaos/federation/run.sh --profile smoke
./chaos/federation/run.sh --profile hostile --network-case baseline
./chaos/federation/run.sh --profile hostile --network-case delay
./chaos/federation/run.sh --profile hostile --network-case loss
./chaos/federation/run.sh --profile hostile --network-case reorder
./chaos/federation/run.sh --profile hostile --network-case bandwidth
./chaos/federation/run.sh --profile hostile
TEREMOQ_FEDERATION_SOAK_SECONDS=1800 \
  ./chaos/federation/run.sh --profile hostile --soak
```

`--soak` is explicit and accepts 300..=3600 seconds. Default hostile duration is
60 seconds. `hostile` defaults to the combined case. The reorder-only case uses
the minimum 1 ms queueing delay required by netem to make reordering effective;
the report records that consumed value. All profiles use a global timeout.

The currently pinned runner image is the already audited Step 7 image built
from `gateway-rs/tests/lab/Dockerfile`. If it is absent, build that Dockerfile
and tag/digest it exactly as the selected profile specifies; the harness refuses
an unpinned or unavailable image.

## Report contract

Generated Markdown lives under `reports/` and is ignored. It contains revision,
toolchain output, kernel, Docker, CPU/memory, profile, seed, requested versus
consumed configuration, effective limits, phase-specific timing samples,
rejection reasons, valid-peer progress, Object counts, aggregate process RSS,
OS tasks/threads and sockets. `PROFILE_PEERS` was removed because it did not
control workload. Smoke marks duration/rate/payload/netem as `not_applicable`;
Rust emits the actual anonymous, wrong-CA, wrong-EKU, expired, valid and delayed
MoQT-setup clients. Hostile consumes its duration, rate, payload and slow-reader
delay and emits its actual relay/publisher/subscriber topology.

Fields unavailable through `moq-rs` are printed as `unobservable`, not zero.
The final zero row means the disposable container/network no longer exists; it
does not claim the library released every allocation before process exit. A
single smoke or hostile run is not leak evidence. A soak report must compare
stable windows before drawing any memory-growth conclusion.

The profile seed is a workload/report identifier. The pinned iproute2 6.1
`netem` CLI has no `seed` option, so the kernel loss/reorder sequence cannot be
replayed bit-for-bit. Reports retain all effective parameters and must not imply
deterministic packet patterns.

## Coverage and explicit gaps

Smoke runs real upstream clients for anonymous, wrong-CA, wrong-EKU and expired
identities, a valid peer, and a peer that has completed `transport_connect` but
delays `Publisher::connect`,
scheduler N+1/recovery, the existing mTLS isolation test and end-to-end MoQT
Objects with two subscriber speeds. `transport_connect` includes QUIC, TLS and
WebTransport CONNECT in the pinned API. A truly pending QUIC/TLS handshake is
`untestable_with_pinned_public_api`; no post-connect sleep is presented as one.

Hostile can apply delay/jitter, loss, reorder, bandwidth, or their combined
profile independently, then runs the reconnect/Object test. Its reader drains
every Object in every Subgroup, and a deterministic regression publishes five
Objects in one Group to prevent the former one-Object-per-GOP bug. The test
preserves encoded payloads and adds no encoder, decoder, or transcoding.

Before that reader correction, fast and slow each received 42 of 1201 Objects.
The first failure was the slow-isolation assertion, not the later 95% threshold:
the reader consumed one Object per 30-Object GOP. ADR-0006 records the root
cause. After the fix, each 60-second baseline, delay/jitter, loss, reorder,
bandwidth and combined case delivered 1201/1201 Objects to the fast reader; the
slow reader delivered 469..481 Objects. Every case cleaned up and returned zero.
These are single finite samples, not capacity or leak-freedom evidence.

The hostile transport publishes only `TrackId::VideoHq`; it contains no audio
or telemetry and has not observed publisher-side drops. It therefore does not
demonstrate multitrack Object Dropping. Multitrack priority is proven only by
the hermetic scheduler tests; MoQT multitrack integration remains pending.

The following remain pending until upstream supplies admission and authenticated
identity hooks:

- real N+1 rejection at pending-handshake and active-session limits;
- exact pending-handshake/task gauges and overload reason events;
- SPIFFE-invalid versus mTLS-valid-but-unauthorized isolation;
- absolute handshake timeout and QUIC Retry policy;
- production soak and slope analysis against a relay with effective bounds.
